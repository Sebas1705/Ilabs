# `vision` module — design

Status: draft for owner approval · Date: 2026-11-21 · Parent: [2026-11-11-ilabs-design.md](2026-11-11-ilabs-design.md)

## Intent

Run an image classifier or an object detector on the device, and get the plumbing around the model exactly right. `vision` turns an RGB image into the tensor a model expects (resize, crop or letterbox, channel order, normalization, layout), reads the model's raw output back (softmax and top-k for classification; box decoding, score filtering and non-maximum suppression for detection), maps boxes back to the original image, and measures the result (top-k accuracy, IoU, average precision). The model itself sits behind a small interface, like the `Embedder` of `rag`. It is the seventh iLabs module and the first one that does not call a language model.

The owner wants it for the portfolio and for interviews, with image classification and object detection as the two tasks. The plumbing is where real bugs live (letterbox geometry, coordinate systems, NMS thresholds, channel order), and it is what an interviewer asks about, so the module is a readable, tested tour of it, with real models running in the demos.

## Goals / non-goals

- Same behavior in Kotlin (KMP, Android + JVM) and TypeScript, pinned by shared fixtures in `contracts/vision/`, like the previous modules.
- Deterministic only: image resizing and cropping, the preprocessing geometry, normalization and layout, softmax, top-k, box decoding and format conversion, score filtering, NMS, the inverse mapping to the original image, IoU and the metrics are in the contract. Real model inference is NOT (floating-point results differ between LiteRT and ONNX Runtime and between devices); a `VisionModel` is scripted in the fixtures and real in the demos.
- Goal: a pluggable `VisionModel` described by a small *model card* (`ModelSpec`: input size, layout, channel order, normalization, output format, labels), so any compatible classifier or detector plugs in without touching the contract.
- Non-goals: decoding image files (JPEG, PNG and EXIF orientation are platform work; the contract starts at raw RGB pixels), training, segmentation, keypoints, OCR, live camera streams, GPU delegates, quantization tooling, model conversion, video. The demos note these.
- Anti-goal: presenting a small mobile model as accurate. The demos show its confidence and its mistakes honestly.

## Approaches considered

- **A. Contract only, scripted model outputs:** deterministic and small, but the demo never runs a real model.
- **B. A + real models behind `VisionModel` in the demos (chosen by the owner):** the contract is A; real models plug in through the interface; the demos show the full path with latency. Cost: real inference is not fixed by fixtures (a smoke test only), and the models have to be obtained and distributed.
- **C. B + live camera, GPU delegates, quantization and benchmarks:** more impressive, much heavier and hard to verify without devices. A later iteration.

## Rules (my calls, to confirm)

**Images.** `Image { width, height, data }` with `data` the `width * height * 3` bytes of 8-bit RGB, row-major, interleaved, top row first. `width` and `height` are integers `>= 1`; the byte count must match (else `invalid_options`). An alpha channel is dropped by the caller (the demos composite on white before conversion; not in the contract).

**Resize.** `resize(image, width, height, method)` with `method` `nearest` or `bilinear`; all arithmetic in IEEE doubles with the operation order written in the contract (only `+ - * /` and floor: bit-identical in both languages). Destination pixel `(x, y)` samples the source at `sx = (x + 0.5) * srcW / dstW - 0.5` (likewise `sy`). `nearest`: `floor(sx + 0.5)` clamped to `[0, srcW - 1]`. `bilinear`: `x0 = floor(sx)`, `fx = sx - x0`, neighbours `x0` and `x0 + 1` clamped to the image, weights `(1 - fx)` and `fx` (likewise y), value `= round-half-up(v00 * (1-fx) * (1-fy) + v10 * fx * (1-fy) + v01 * (1-fx) * fy + v11 * fx * fy)` clamped to `[0, 255]`; `round-half-up(v) = floor(v + 0.5)`. Fixtures compare the integer bytes exactly.

**Preprocessing geometry.** `preprocessGeometry(srcW, srcH, spec)` returns the mapping used both to build the input and to map boxes back: `mode` `stretch` (scale each axis independently), `centerCrop` (scale so the image covers the target, crop the centered window; crop offsets `floor((scaledW - dstW) / 2)`), `letterbox` (scale by `min(dstW/srcW, dstH/srcH)`, resize to `round-half-up(src * scale)` per axis, pad with `padValue` (default 114) centered with `padX = floor((dstW - newW) / 2)`, `padY` likewise). The geometry is `{ scaleX, scaleY, offsetX, offsetY, newW, newH }` in doubles; `unmapBox` inverts it: `(x - offsetX) / scaleX`, `(y - offsetY) / scaleY`, then clamps to the original image.

**Normalization and layout.** `toTensor(image, spec)`: after resize/crop/pad, channel order `rgb` or `bgr`, then per channel `(v * scale - mean[c]) / std[c]` in doubles (`scale` default `1`, e.g. `1/255`; `mean`, `std` default `0` and `1`), laid out `nhwc` or `nchw`. A `uint8` input spec passes the bytes through untouched. The tensor is `{ shape: [1, ...], data }` with doubles (the real-model adapters convert to float32 at the boundary; not in the contract). Fixtures compare values with an absolute tolerance of `1e-9`.

**Classification output.** `postprocessClassification(output, spec, { topK?, minScore? })`: `output` is a vector of logits (`outputType: "logits"`) or probabilities (`"probabilities"`); logits go through a numerically stable softmax (`exp(x - max)` then divide by the sum, in index order); probabilities are used as given (they must be finite and `>= 0`). Result: up to `topK` (default 5) entries `{ index, label, score }` ordered by descending score, ties by ascending index; entries below `minScore` (default 0) are dropped; `label` comes from `spec.labels[index]` (absent label: `"#<index>"`). `softmax` uses `exp`, which can differ in the last bits between platforms: scores are compared with tolerance `1e-9` and ranks exactly; fixtures never contain scores closer than `1e-9` that are not exactly equal.

**Detection output.** Two decoders, selected by `spec.output.format`:
- `ssd`: the already post-processed output of a detection model: tensors `boxes` (`[n, 4]` as `[ymin, xmin, ymax, xmax]`), `classes` (`[n]`, indices), `scores` (`[n]`) and optionally `count`; coordinates normalized to `[0, 1]` of the model input (or pixels of the model input when `coordinates: "pixels"`).
- `rows`: raw rows `[n, 4 + C]` (`boxFormat` `xywh` (center x, center y, width, height) or `xyxy`; then `C` class scores, no objectness; the best class per row is the detection).
Then `postprocessDetections(outputs, spec, geometry, { scoreThreshold?, iouThreshold?, maxDetections?, nms? })`: convert every box to `xyxy` in model-input pixels, drop rows below `scoreThreshold` (default `0.3`), apply class-aware NMS when `nms` is true (default true for `rows`, false for `ssd`), cut to `maxDetections` (default 100), map each box back to the original image with `unmapBox`, and clamp. Result: detections `{ box: { x1, y1, x2, y2 }, classIndex, label, score }` ordered by descending score, ties by ascending original row index.

**NMS.** `nms(detections, iouThreshold)`: per class, repeatedly keep the highest-scoring box (ties by ascending original index) and drop the remaining boxes of that class whose `IoU > iouThreshold` (strictly greater) with it. `iou(a, b)` is intersection over union of `xyxy` boxes in doubles; a zero or negative area union gives `0`; boxes touching on an edge have intersection `0`.

**Metrics.** `iou`, `topKAccuracy(predictions, truths, k)` (`predictions`: one ranked index list per sample, `truths`: the true index per sample, `k >= 1` else `invalid_options`; the fraction of samples whose true index is among the first `k` predicted indices; an empty sample set gives `0`), and `averagePrecision(detections, truths, { iouThreshold })` per class with all-point interpolation (VOC2010 style: see the rulings below), `meanAveragePrecision` over the classes that have truths. Exact doubles computed in the order the contract writes, compared with tolerance `1e-9`.

**Pipeline.** `classify(model, image, spec, options)` and `detect(model, image, spec, options)`: validate the options, `preprocess`, ONE `model.run(tensor)` call, postprocess, return `{ results, timing: { preprocessMs, inferenceMs, postprocessMs } }` (timings come from an injectable clock so tests are exact; real clocks in the demos); errors from the model propagate unchanged. `VisionModel { run(input: Tensor): Promise<NamedTensors> }`; `scriptedModel(outputs)` for tests and fixtures; `ModelSpec` is plain data validated by `parseModelSpec(json)` (`invalid model spec: <reason>`, prefix pinned, as `invalid suite` in `evals`).

**Errors.** `VisionError(kind)`: `invalid_spec`, `invalid_options`, `invalid_output` (a model output with the wrong shape, a non-finite number or a class index outside the labels range when labels are given), so malformed outputs are rejected before any result.

**Fixtures.** `contracts/vision/<name>.json`, kinds: `resize` (a tiny image as an array of bytes, target size, method → bytes), `geometry` (source size + spec → geometry and mapped boxes), `tensor` (image + spec → shape and values), `softmax`/`classify` (output + spec → entries), `decode` (output tensors + spec + geometry → detections), `nms`, `metrics` (`iou`, `topk`, `ap`, `map`), `pipeline` (image + spec + scripted model outputs → results, the single model call asserted), `spec` (invalid specs → `invalid_spec`) and `invalid` (option errors). About 120 fixtures: resize edges (1x1, upscale and downscale ratios, odd sizes, clamping at borders, half-pixel centers, nearest ties), geometry per mode (stretch, centerCrop with odd differences, letterbox with odd padding, extreme aspect ratios), channel order and layout, normalization, softmax stability (large logits, ties), top-k with ties and `minScore`, decode formats (both box formats, normalized and pixel coordinates, count field), score threshold edge, NMS (class-aware, strict `>` boundary, ties by index, identical boxes), unmapping through every geometry, metrics (perfect, none, partial, duplicate detections as false positives, multiple classes, empty sets), invalid outputs and specs. Harness rules like `evals` and `rag`: unknown keys rejected on the raw JSON, guard `>= <count>`, aggregated failures, malformed fixtures `invalid fixture:`.

## Demos

A web page and an Android screen over the same sample images and the same model cards. (1) **Classify**: pick a sample image or load your own; see the image, the tensor preview (the resized image as the model sees it, with a note on the geometry), the top-k labels with probabilities (text plus bars), and the three timings. (2) **Detect**: the same flow with the boxes drawn over the original image (each box labelled with class and score as text, not colour alone), a score-threshold and an IoU-threshold control that re-run only the postprocessing, and the geometry shown. (3) **Backends**: a switch between the scripted model (the sample's recorded output from the fixtures, available everywhere and in tests) and the real model (LiteRT on Android, ONNX Runtime Web in the browser); when the model files are missing the demo says so and stays on the scripted backend. A note says the models are small and make mistakes. es + en, light/dark, same shell as the other modules; one entry in the web route registry and the Android module home.

## Models (my calls, to confirm)

- Classification: a MobileNet/EfficientNet-Lite class model (ImageNet 1k labels); detection: an SSD/EfficientDet-Lite class model (COCO 80 labels). Android uses `.tflite` files through LiteRT; the web uses `.onnx` files through ONNX Runtime Web (WASM). Both runtimes are Apache 2.0 / MIT; the builder picks specific models, verifies their licenses (Apache 2.0 or equivalent; no AGPL models such as Ultralytics YOLO) and records the exact source and checksum in the module README.
- Model files are NOT committed: a documented script downloads them into a git-ignored folder and verifies their checksums; the Android build copies them into the demo assets when present; the web demo loads them from the same folder in dev or from a configurable URL. Without them, both demos fall back to the scripted backend. The release APK built for Firebase App Distribution may bundle them (owner step, documented).
- The sample images are small, license-free (generated or public domain) and listed with their licenses; the web and Android demos use the same ones, stored with the demo assets.

## Left to the builder

File layout, the exact model choices and download source, the ONNX Runtime Web and LiteRT adapter code, UI copy and layout, how boxes and tensor previews are drawn, the sample images, and the exact wording of option validation errors.

## Rulings after the builder check (my calls, binding for the contract)

**ModelSpec.** Plain JSON, unknown keys rejected (`invalid model spec: <reason>`): `{ "input": { "width", "height", "layout": "nhwc"|"nchw", "channels": "rgb"|"bgr", "mode": "stretch"|"centerCrop"|"letterbox", "resample": "nearest"|"bilinear", "padValue"?, "dtype": "float"|"uint8", "scale"?, "mean"?, "std"? }, "output": { "type": "logits"|"probabilities" } for classifiers, or { "format": "ssd"|"rows", ... } for detectors, "labels"?: [string], "labelOffset"?: integer }`. The contract author pins every field name, default and validation reason in `contracts/vision/README.md`; `mean`/`std` have exactly 3 entries, `std` entries are non-zero, `dtype: "uint8"` forbids `scale`/`mean`/`std`, sizes are integers `>= 1`.

**Output decoders.** A leading batch dimension of size 1 is squeezed (shape-based). `ssd`: `boxOrder` `"yxyx"` (default, `[ymin, xmin, ymax, xmax]`) or `"xyxy"`; `coordinates` `"normalized"` (default) or `"pixels"`; `count` (a float in TFLite outputs) truncates `n` (floor, clamped to `[0, n]`); `labelOffset` is subtracted from the model's class id to get the index into `labels` (COCO 91-id models use the 90/91-entry list with offset 1; ImageNet models with a background class use offset 1). `rows`: `transposed` (rows are columns: `[4 + C (+1), n]`), `objectness` (column 4 is multiplied into the class scores), `boxFormat` `"xywh"`|`"xyxy"`, `scoreActivation` `"none"`|`"sigmoid"` (a pinned logistic function, compared with tolerance). The demos' real models use the `ssd` format on both platforms (SSD-MobileNet / EfficientDet-Lite class, Apache 2.0); the `rows` decoder, NMS and the threshold controls are exercised by fixtures and by the scripted backend of the demos (recorded raw rows), because no permissively licensed raw-rows detector is required. A sample whose raw rows are scripted lets the user move the score and IoU thresholds and see NMS work.

**Geometry.** `scaleX`/`scaleY` are the ACTUAL ratios between the resized content and the source: `stretch`: `dstW/srcW`, `dstH/srcH`; `letterbox`: `scale = min(dstW/srcW, dstH/srcH)`, `newW = max(1, round-half-up(srcW * scale))` (likewise `newH`), `scaleX = newW/srcW`, `scaleY = newH/srcH`, `offsetX = padX`, `offsetY = padY` (positive: content starts at `(padX, padY)`); `centerCrop`: `scale = max(dstW/srcW, dstH/srcH)`, `scaledW = max(dstW, round-half-up(srcW * scale))` (likewise `scaledH`), the WHOLE image is resized to `scaledW x scaledH` and the window `[cropX, cropX + dstW)` with `cropX = floor((scaledW - dstW) / 2)` is cut, `scaleX = scaledW/srcW`, `offsetX = -cropX`. Mapping a model-input coordinate back: `(x - offsetX) / scaleX`. After mapping and clamping to the original image, boxes whose clamped width or height is `0` are dropped.

**Normalization.** Order: channel swap (`bgr`) first; then for output channel position `c`, `(v * scale - mean[c]) / std[c]` (`mean`/`std` index the OUTPUT channel order); `padValue` is a raw byte written before the swap and the normalization (padding is normalized like pixels); `dtype: "uint8"` still applies the channel swap and the layout and skips scale/mean/std.

**Detection order.** (1) take the best class per row (`rows`: lowest class index on ties; scores after activation/objectness), (2) keep rows with `score >= scoreThreshold`, (3) swap coordinates if `x2 < x1` or `y2 < y1`, (4) NMS when enabled, (5) sort by descending score (ties by ascending original row index), (6) cut to `maxDetections`, (7) map back, clamp, drop zero-area boxes. `ssd` without NMS follows the same order.

**Metrics.** `averagePrecision` input: flat lists `detections: [{ image, classIndex, score, box }]` and `truths: [{ image, classIndex, box }]` (`image` is an opaque string id). Per class: sort that class's detections by descending score (ties by ascending input index); each detection takes the truth of the SAME image and class with the highest IoU (ties: lowest truth index); it is a true positive when that IoU `>= iouThreshold` and the truth has not been taken, else a false positive (VOC style: a detection never falls back to a second-best truth); precision/recall at every detection, the precision envelope (non-increasing from the right), area under the curve over recall (all-point interpolation). A class with truths and no detections has AP `0`; a class with detections and no truths is skipped; `meanAveragePrecision` averages the APs of the classes with truths and is `0` when there are none. `iou` of a zero-area union is `0`.

**Pipeline and clock.** `Clock { nowMs(): number }` (Kotlin: `fun interface Clock { fun nowMs(): Double }`, real clocks in the demos, a scripted one in tests); `nowMs` is called exactly four times in this order: before preprocessing, after preprocessing, after the model call, after postprocessing, and `preprocessMs`, `inferenceMs`, `postprocessMs` are the successive differences. `VisionModel.run` is `suspend` in Kotlin. `scriptedModel(outputs)` ignores the input values, records every call, and returns the scripted named tensors; the `pipeline` fixtures assert exactly one call and compare the recorded input tensor's shape and values (tolerance `1e-9`) with the expected `tensor`.

**Samples for the demos.** The contract fixtures are hand-built. The demos' sample images are a small shared set (written or generated for the repo or public domain, with a license list) stored with the demo assets, together with the recorded raw outputs of the real models for each sample (captured once with the real models and committed as small JSON next to the images: the scripted backend), so both demos work without model files. A real-model smoke test (classification of a sample image returns the expected top label) is a local, manual step documented in the module README; CI never needs model files.

### Supersession note (after the contract reviews)

`contracts/vision/README.md` is the authority for every detail of the contract; where it differs from the paragraphs above, the README wins. Known differences, all decided in the contract: no separate `softmax`/`invalid` fixture kinds (any kind may expect `{ "error": ... }`; about 320 fixtures instead of about 120); `postprocessDetections(outputs, spec, geometry, source, options)` takes the source image size; geometry fields are `newWidth`/`newHeight`; `decode` fixtures compute the geometry from `srcWidth`/`srcHeight`; `pipeline` fixtures compare the recorded `input` tensor and carry `clockReads`; sizes are integers from 1 to 16,384 per side; the zero-area drop rule is `width <= 0 or height <= 0` after clamping (`unmapBox` never reorders swapped boxes); the class index is validated on every row before the threshold; detect options are validated before the first clock read; timings are not clamped; JSON `null` for any optional key or option is a bad value; non-finite numbers in outputs are `invalid_output`; and "doubles win over exact math" for every rounding that the contract writes out.
